# Звіт з налаштування сповіщень (CloudWatch Alarms + SNS)

## 1. Умова сповіщення
- **Метрика:** `AWS/ECS CPUUtilization`
- **Поріг спрацювання:** > 70%
- **Тривалість:** Протягом 2 хвилин (`evaluation_periods = 2`, `period = 60`)
- **Канал доставки:** Email через AWS SNS Topic (`cloud-lab1-alerts`)

## 2. Обґрунтування умови
Вимога перевірки перетину порогу протягом 2 хвилин поспіль (2 періоди по 60 сек) запобігає хибним спрацюванням через випадкові короткочасні сплески процесора (наприклад, під час старту застосунку). Лист надсилається тільки тоді, коли сервіс дійсно тривалий час перебуває під критичним навантаженням.

## 3. Час реакції та оцінка прийнятності
- **Час від початку сталого навантаження до приходу листа ALARM:** ~2–3 хвилини (складається з 2 хвилин оцінки метрики AWS + затримка доставки електронної пошти SNS).
- **Час до приходу листа OK:** ~5-6 хвилин після завершення тесту (з урахуванням спаду CPU та періоду стабілізації).

### Оцінка прийнятності
Для некритичних веб-сервісів затримка сповіщення у 2-3 хвилини є повністю прийнятною, оскільки вона виключає хибні тривоги серед ночі. Для високонавантажених фінансових систем цей час зменшують до 1 хвилини або налаштовують додаткові сповіщення на рівні латентності (p95 > 500ms).

## 4. Підтвердження сповіщень (Скріншоти листів)
*(Сюди вставляються скріншоти отриманих листів)*
1. **Лист 1 (Стан ALARM):** Тема `ALARM: "cloud-lab1-cpu-high-alarm" in eu-north-1`.
2. **Лист 2 (Стан OK):** Тема `OK: "cloud-lab1-cpu-high-alarm" in eu-north-1`.
